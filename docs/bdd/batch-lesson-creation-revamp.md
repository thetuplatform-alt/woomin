# 批次建立單元改版 + AI 生成講義整合 — BDD 規格

## 概述
將現有的「AI 快速建立」功能改版為更直覺的「新增批次單元」，強制三層資料夾結構（root → 章節 → 單元），並整合 AI 講義生成功能（使用用戶自訂的 Gemini API Key 與模型）。同時重命名按鈕、增強 Empty State、統一 AI API、改進模型選擇 UI。

---

## 行為規格

### 場景 1：左側面板按鈕重命名
**Given** 用戶在課程內容編輯頁面
**When** 用戶查看左側大綱面板底部按鈕區
**Then** 看到兩個按鈕：「新增批次單元」（取代原「AI 快速建立」）和「新增單一單元」（取代原「新增章節」）

### 場景 2：Empty State 增強
**Given** 用戶尚未選取任何單元（中間面板顯示 Empty State）
**When** 用戶查看 Empty State 區域
**Then** 在「尚無選取單元」提示文字下方看到兩張卡片式按鈕：
- 「新增批次單元」：有 icon、標題、描述文字（說明可上傳資料夾批量建立）
- 「新增單一單元」：有 icon、標題、描述文字（說明可逐步新增章節與單元）

### 場景 3：新增單一單元觸發新增章節 Dialog
**Given** 用戶點擊「新增單一單元」按鈕（無論在左側面板底部或 Empty State）
**When** 按鈕被點擊
**Then** 打開新增章節 Dialog（與原「新增章節」行為相同）

### 場景 4：三層資料夾結構驗證
**Given** 用戶拖入或選擇一個資料夾
**When** 系統解析資料夾結構
**Then** 系統驗證必須是嚴格三層結構：
- 第一層：root（用戶拖入的資料夾）
- 第二層：章節資料夾（資料夾名稱即章節名）
- 第三層：單元資料夾（資料夾名稱即單元名）
如果不符合三層結構，拒絕並顯示錯誤提示，說明正確的資料夾格式

### 場景 5：單元資料夾內檔案識別
**Given** 系統正在解析第三層（單元）資料夾
**When** 資料夾內有多種檔案
**Then** 系統自動識別：
- 影片：`.mp4`、`.mov`，多個時取第一個，MP4 優先於 MOV
- 文字：`.md`、`.srt`，Markdown 優先於 SRT
- 其他檔案忽略

### 場景 6：結構預覽顯示
**Given** 資料夾結構驗證通過
**When** 系統進入預覽階段
**Then** 以樹狀結構顯示：章節名稱、單元名稱、各單元識別到的影片/字幕/Markdown 狀態

### 場景 7：AI 講義生成使用用戶自訂設定
**Given** 用戶已在系統設定中配置 Gemini API Key 和模型
**When** 批次處理中需要從 SRT 字幕生成講義
**Then** 系統使用用戶設定的 API Key 和模型（而非寫死的模型）

### 場景 8：未設定 API Key 時的引導（批次建立）
**Given** 用戶未在系統設定中配置 Gemini API Key
**When** 用戶啟動批次建立流程
**Then** 系統提供兩個選項：
1. 引導設定 API Key（彈出設定介面）
2. 跳過 AI 講義生成（僅建立章節/單元/上傳影片，不生成講義內容）

### 場景 9：未設定 API Key 時的引導（單元編輯器 AI 按鈕）
**Given** 用戶未在系統設定中配置 Gemini API Key
**When** 用戶點擊單元編輯器中的「AI 生成講義」按鈕
**Then** Modal 先顯示 API Key 設定介面，引導用戶配置後再繼續

### 場景 10：AI 模型設定表單改進
**Given** 用戶在系統設定的 AI 模型區塊
**When** 用戶選擇 Gemini 模型
**Then** 提供預設選項（如 gemini-2.5-flash）加一個「其他」選項，選擇「其他」後出現輸入框讓用戶手動輸入模型名稱

### 場景 11：Markdown 檔案直接作為講義內容
**Given** 單元資料夾內有 .md 檔案
**When** 系統處理該單元
**Then** 直接讀取 Markdown 檔案內容作為單元講義，不再透過 AI 生成

### 場景 12：SRT 字幕透過 AI 生成講義
**Given** 單元資料夾內有 .srt 檔案但無 .md 檔案
**When** 系統處理該單元且 API Key 已設定
**Then** 透過 Gemini AI 將 SRT 字幕轉化為結構化講義

### 場景 13：統一 AI 講義生成 API
**Given** 單元編輯器的「AI 生成講義」按鈕或批次建立流程需要生成講義
**When** 系統呼叫 AI 生成 API
**Then** 使用統一的 API route，從資料庫讀取用戶配置的 Gemini API Key 和模型

## Acceptance Criteria

- [ ] AC-01：左側面板底部「AI 快速建立」改名為「新增批次單元」，icon 更換為非 Sparkles 的批量相關 icon
- [ ] AC-02：左側面板底部「新增章節」改名為「新增單一單元」
- [ ] AC-03：「新增單一單元」按鈕行為不變，仍觸發新增章節 Dialog
- [ ] AC-04：Empty State 增加兩張卡片式按鈕（新增批次單元 + 新增單一單元），含 icon、標題、描述
- [ ] AC-05：Empty State 中「新增批次單元」點擊後打開批次建立 Dialog
- [ ] AC-06：Empty State 中「新增單一單元」點擊後打開新增章節 Dialog
- [ ] AC-07：資料夾解析改為嚴格三層結構驗證（root → 章節 → 單元），不符合時拒絕並顯示格式說明
- [ ] AC-08：單元資料夾內支援 `.mp4`、`.mov`、`.srt`、`.md` 檔案識別
- [ ] AC-09：多個影片檔取第一個，MP4 優先於 MOV
- [ ] AC-10：多個文字檔，Markdown 優先於 SRT
- [ ] AC-11：有 `.md` 檔時直接作為講義內容，不經過 AI 生成
- [ ] AC-12：有 `.srt` 無 `.md` 時，若 API Key 已設定則透過 AI 生成講義
- [ ] AC-13：AI 生成 API（`ai-generate-notes/route.ts`）改用 `ai-sdk` + `streamText` 寫法，從資料庫讀取用戶的 Gemini API Key 和模型
- [ ] AC-14：批次建立中的 AI 生成（`ai-course/generate-content/route.ts`）也改為從資料庫讀取用戶的 API Key 和模型
- [ ] AC-15：未設定 API Key 時，批次建立流程提供「設定 API Key」或「跳過講義生成」兩個選項
- [ ] AC-16：跳過講義生成時，僅建立章節/單元/上傳影片，講義內容留空
- [ ] AC-17：AI 模型選擇改為預設選項 + 「其他」自訂輸入框，支援用戶手動填入新模型名
- [ ] AC-18：資料夾格式說明在批次建立 Dialog 的拖放區域中清楚顯示三層結構範例
- [ ] AC-19：TypeScript 型別檢查通過，無編譯錯誤

## 排除範圍（Out of Scope）
- 影片轉檔或格式轉換功能
- SRT 字幕自動生成（需外部工具產出）
- 支援超過三層的資料夾結構
- 影片來源的 AI 講義生成（僅字幕/Markdown 來源）
