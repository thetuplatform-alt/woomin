# 系統設定頁面重新設計（Ghost 風格） — BDD 規格

## 概述
將後台「系統設定」從目前的 Tab 切換式（多頁路由）改為 Ghost 風格的單頁長捲動佈局，並在左側增加設定專用側邊欄，讓管理者可快速跳轉到各區塊。同時將「隱私權政策」和「服務條款」從系統設定中拉出，變成後台側邊欄的獨立頁面。

## 行為規格

### 場景 1：進入系統設定頁面
**Given** 管理者（ADMIN）已登入並進入後台
**When**  點擊側邊欄的「系統設定」
**Then**  看到一個單頁式的設定頁面，包含左側設定導覽欄和右側長捲動內容區，內容依序為：基本設定 → 版面設定 → 金流設定 → Email 設定 → 分析追蹤

### 場景 2：左側設定導覽欄快速跳轉
**Given** 管理者在系統設定頁面
**When**  點擊左側導覽欄中的某個區塊名稱（如「金流設定」）
**Then**  頁面平滑捲動到該區塊的位置

### 場景 3：捲動時導覽欄高亮同步
**Given** 管理者在系統設定頁面
**When**  手動向下捲動頁面，使「Email 設定」區塊進入視窗
**Then**  左側導覽欄中「Email 設定」項目自動高亮，其他項目取消高亮

### 場景 4：隱私權政策作為獨立頁面
**Given** 管理者已登入後台
**When**  在後台側邊欄（主側邊欄）看到「隱私權政策」選項並點擊
**Then**  導航到 `/admin/privacy` 獨立頁面，可編輯隱私權政策的 Markdown 內容

### 場景 5：服務條款作為獨立頁面
**Given** 管理者已登入後台
**When**  在後台側邊欄（主側邊欄）看到「服務條款」選項並點擊
**Then**  導航到 `/admin/terms` 獨立頁面，可編輯服務條款的 Markdown 內容

### 場景 6：各設定區塊功能保持不變
**Given** 管理者在新的單頁設定頁面
**When**  編輯任何一個區塊的表單並送出
**Then**  該區塊的儲存行為與原本各獨立頁面完全一致（包含驗證、錯誤提示、成功通知）

### 場景 7：手機版響應式
**Given** 管理者使用手機或小螢幕裝置
**When**  進入系統設定頁面
**Then**  左側設定導覽欄隱藏（或變成頂部水平列），內容區域佔滿寬度，仍可正常捲動和操作

## Acceptance Criteria
- [ ] AC-01：系統設定頁面（`/admin/settings`）為單頁長捲動佈局，所有設定區塊（基本設定、版面設定、金流設定、Email 設定、分析追蹤）依序垂直排列
- [ ] AC-02：頁面左側有固定（sticky）的設定導覽欄，列出所有區塊名稱
- [ ] AC-03：點擊左側導覽欄的區塊名稱，頁面平滑捲動到對應區塊
- [ ] AC-04：捲動頁面時，左側導覽欄的高亮項目根據當前可見區塊自動切換（使用 Intersection Observer）
- [ ] AC-05：「隱私權政策」從設定 Tab 中移除，改為後台側邊欄的獨立頁面（路由 `/admin/privacy`）
- [ ] AC-06：「服務條款」從設定 Tab 中移除，改為後台側邊欄的獨立頁面（路由 `/admin/terms`）
- [ ] AC-07：後台主側邊欄（sidebar.tsx）新增「隱私權政策」和「服務條款」兩個導覽項目，標記為 adminOnly
- [ ] AC-08：原有的 `SettingsNav`（Tab 按鈕列）被移除或不再使用
- [ ] AC-09：各設定區塊的表單功能、驗證、儲存邏輯完全保留不變
- [ ] AC-10：手機版（< 768px）時左側導覽欄隱藏或轉為水平列，不遮擋內容
- [ ] AC-11：舊的設定子路由（`/admin/settings/payment`、`/admin/settings/email`、`/admin/settings/layout`）不再需要，但不會導致 404（可重導到 `/admin/settings`）
- [ ] AC-12：分析追蹤設定（原本在基本設定的 Tab 內）在新頁面中作為獨立區塊顯示

## 排除範圍（Out of Scope）
- 不修改任何 Server Action 或 Zod 驗證邏輯
- 不修改表單元件內部的功能邏輯
- 不新增任何設定項目
- 不修改前台的隱私權政策 / 服務條款顯示頁面
