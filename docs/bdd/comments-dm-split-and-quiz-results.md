# 留言/私訊拆分 + 老師端私訊重設計 + 老師查看測驗結果 — BDD 規格

## 概述

本次改造涵蓋三個獨立但相關的範圍，目標是讓「課程留言」「老師私訊」「測驗結果」三件事在前後台都各自成為清晰、直覺、體驗良好的功能：

1. **留言 / 私訊拆分**：目前「課程留言」與「老師私訊」在 UI 層被綁在同一個元件 / 同一頁（前台一顆「評論」按鈕內用 tab 切換；後台一個「留言管理」分頁混兩張表）。資料層與 API 早已分離。本次把兩者在前台、後台、課程編輯頁三處**完全拆成獨立入口與獨立頁面**。
2. **老師端私訊重設計**：把目前「扁平大表 + 無未讀提示 + 無對話脈絡」的私訊管理，重做成 **Messenger 式對話收件匣**（依學員聚合對話串、未讀紅點、最後訊息預覽、行內回覆、附件）。
3. **老師查看學員測驗結果**：目前後台**完全沒有**讓老師查看學員測驗作答的介面（`QuizAttempt` 有存資料，但無對應 server action 與 UI）。本次沿用「作業」既有的提交查看模式（`getAssignmentSubmissions` / `submission-list.tsx`），新增完整的測驗結果查看（成績、逐題對照、統計、CSV 匯出）。

> **資料庫**：三個範圍在「核心行為」上**皆不需 schema migration**——`LessonComment`、`LessonPrivateMessage`、`QuizAttempt` 既有欄位已足夠。涉及 schema 異動的項目（如私訊軟刪除）一律列入 Out of Scope。

## 範圍一：留言 / 私訊拆分

### 場景 1.1：學員在播放頁看到兩個獨立入口
**Given** 學員已登入並進入已購買課程的單元播放頁
**When** 學員查看播放頁的動作列
**Then** 看到「課程留言」與「私訊老師」**兩個各自獨立的按鈕**（不同 icon、不同文字），而非單一「評論」按鈕

### 場景 1.2：開啟「課程留言」只看到群組留言
**Given** 學員在播放頁
**When** 點擊「課程留言」入口
**Then** 開啟的面板**只**包含群組留言內容：可看到其他學員留言、可發表留言、可使用匿名選項；面板中**不出現**任何私訊內容或「私訊老師」分頁

### 場景 1.3：開啟「私訊老師」只看到一對一私訊
**Given** 學員在播放頁
**When** 點擊「私訊老師」入口
**Then** 開啟的面板**只**包含與老師的一對一私訊：可看到自己與老師的往返、可發送訊息與附件；面板中**不出現**群組留言、**不提供**匿名選項

### 場景 1.4：兩個面板狀態彼此獨立
**Given** 學員開啟其中一個面板並輸入內容
**When** 切換去開另一個面板
**Then** 兩面板各自維護獨立狀態（草稿、載入、送出冷卻），互不污染

### 場景 1.5：後台 sidebar 拆成兩個獨立分頁
**Given** ADMIN / EDITOR / INSTRUCTOR 登入後台
**When** 查看左側選單
**Then** 看到「課程留言」與「老師私訊」**兩個獨立選單項目**（取代原本單一的「留言管理」），各自連到獨立路由

### 場景 1.6：後台「課程留言」頁只管理群組留言
**Given** 老師進入「課程留言」頁
**When** 頁面載入
**Then** 只列出群組留言（可回覆、可刪除、可看匿名留言真實身分），**完全不含**任何私訊資料

### 場景 1.7：課程編輯頁的 tab 同步拆開
**Given** 老師進入某課程的後台編輯頁
**When** 查看編輯頁的 tab 列
**Then** 原本單一「留言」tab 拆成「留言」與「私訊」**兩個獨立 tab**，各自頁面內容不混雜

### 場景 1.8：INSTRUCTOR 課程隔離維持不變
**Given** 角色為 INSTRUCTOR 的老師
**When** 進入「課程留言」或「老師私訊」頁
**Then** 只看得到自己有權管理的課程之留言 / 私訊（沿用既有 `manageableCourseWhereForUser` 隔離），看不到他人課程資料

## 範圍二：老師端私訊「對話式收件匣」重設計

### 場景 2.1：對話清單以學員聚合呈現
**Given** 多位學員曾傳送私訊
**When** 老師進入「老師私訊」頁
**Then** 左側顯示**對話清單**，每筆代表一位學員（含頭像、姓名）並顯示：最後一則訊息預覽、最後訊息時間；以最新活動排序

### 場景 2.2：未讀視覺提示
**Given** 某對話中存在學員傳來、老師尚未讀的訊息（學員訊息且 `readByTeacher = false`）
**When** 老師查看「老師私訊」頁與後台 sidebar
**Then** 該對話在清單上顯示**未讀紅點 / 未讀數**；後台 sidebar 的「老師私訊」項目顯示**總未讀數 badge**

### 場景 2.3：開啟對話顯示完整往返並標記已讀
**Given** 老師在對話清單
**When** 點選某一個對話
**Then** 右側依時間序顯示該學員的完整往返訊息（含附件可下載），老師訊息與學員訊息**視覺上明確區分**；開啟後該對話內所有學員未讀訊息被標記為已讀，未讀紅點消失

### 場景 2.4：行內回覆，無需開 Dialog
**Given** 老師已開啟某對話
**When** 在右側輸入框輸入文字並送出
**Then** 訊息**即時**附加到對話串底部、標記為老師訊息（`isFromTeacher = true`）、觸發既有的「老師回覆」email 通知給學員；輸入框清空，全程不跳出獨立 Dialog

### 場景 2.5：老師回覆可附帶附件
**Given** 老師在某對話的回覆輸入區
**When** 老師附加檔案並送出
**Then** 附件隨訊息一併送出並顯示在對話串中（學員端可下載）

### 場景 2.6：篩選未回覆
**Given** 對話清單同時有「已回覆」與「待回覆」對話
**When** 老師切換到「待回覆」篩選
**Then** 清單只顯示存在學員未讀 / 未回訊息的對話

### 場景 2.7：空狀態
**Given** 老師有權管理的範圍內目前沒有任何私訊
**When** 進入「老師私訊」頁
**Then** 顯示友善的空狀態提示，而非空白畫面或錯誤

## 範圍三：老師查看學員「測驗結果」

### 場景 3.1：作業管理頁正名並顯示測驗查看入口
**Given** 某課程的某單元設有測驗且至少一位學員已作答
**When** 老師進入該課程後台的「作業 / 測驗」管理頁（原「作業」頁正名）
**Then** 該單元的測驗區塊顯示作答次數，並有「查看作答結果」按鈕（與「作業」的「批改作業」按鈕並列同一套互動模式）

### 場景 3.2：測驗編輯器徽章可點入查看
**Given** 老師在課程內容 tab 的測驗編輯器，且該測驗已有作答
**When** 老師查看「X 次作答」徽章
**Then** 該徽章為可點擊入口，點擊後可進入 / 開啟該測驗的作答結果檢視

### 場景 3.3：列出全班作答總覽
**Given** 老師開啟某測驗的作答結果
**When** 結果面板載入
**Then** 列出該測驗**所有學員**的作答：每列含學員姓名 / email、得分、通過與否、作答時間

### 場景 3.4：統計總覽
**Given** 老師開啟某測驗的作答結果
**When** 面板載入
**Then** 頂部顯示統計：總作答人次、通過率、平均分（並呈現分數分布）

### 場景 3.5：逐題作答 vs 正解對照
**Given** 老師在作答結果列表
**When** 展開某位學員的某次作答
**Then** 顯示該次作答的每一題：學員的答案、正確答案、對 / 錯標示，以及（若題目有設定）題目解析

### 場景 3.6：多次作答皆可見
**Given** 某學員對同一測驗作答多次
**When** 老師查看該測驗結果
**Then** 老師可看到該學員的多次作答紀錄（不會只顯示一筆而遺漏其他次）

### 場景 3.7：CSV 匯出
**Given** 老師在某測驗的作答結果頁
**When** 點擊「匯出 CSV」
**Then** 下載一份 CSV，包含全班成績（至少：學員姓名、email、得分、通過與否、作答時間）

### 場景 3.8：權限與課程隔離
**Given** 老師查看測驗結果
**When** 載入資料
**Then** 僅有權管理該課程者可查看（沿用 `requireCourseManageAccess` / `manageableCourseWhereForUser`）；INSTRUCTOR 看不到非自己課程的測驗結果；學員端查看自己測驗的行為不受本次改動影響

### 場景 3.9：無人作答的空狀態
**Given** 某測驗尚無任何學員作答
**When** 老師開啟其作答結果
**Then** 顯示「尚無作答」提示，而非錯誤或空白

## Acceptance Criteria

### 範圍一：留言 / 私訊拆分
- [x] AC-01：前台播放頁動作列出現「課程留言」與「私訊老師」兩個獨立入口（非單一「評論」按鈕）。
- [x] AC-02：「課程留言」面板只渲染群組留言（`LessonComment`），不含任何私訊資料、無「私訊老師」分頁。
- [x] AC-03：「私訊老師」面板只渲染一對一私訊（`LessonPrivateMessage`），不含群組留言、無匿名選項，且保留附件能力。
- [x] AC-04：兩面板的本地狀態（草稿、送出冷卻等）彼此獨立，互不影響。
- [x] AC-05：後台 sidebar 出現「課程留言」與「老師私訊」兩個獨立項目，原單一「留言管理」混合入口不再存在。
- [x] AC-06：後台「課程留言」頁只查得到 / 只渲染群組留言；「老師私訊」頁只查得到 / 只渲染私訊。
- [x] AC-07：課程後台編輯頁的 tab 由單一「留言」拆為「留言」與「私訊」兩個獨立 tab，內容不混雜。
- [x] AC-08：INSTRUCTOR 在兩個新頁面只能看到自己可管理課程的資料（課程隔離未被破壞）。

### 範圍二：老師端私訊對話收件匣
- [x] AC-09：「老師私訊」頁左側以「學員」為單位聚合對話清單，顯示頭像 / 姓名、最後訊息預覽與時間，依最新活動排序。
- [x] AC-10：存在學員未讀訊息（`isFromTeacher = false` 且 `readByTeacher = false`）的對話顯示未讀紅點 / 未讀數。
- [x] AC-11：後台 sidebar 的「老師私訊」項目顯示總未讀數 badge（有未讀時）。
- [x] AC-12：點開對話後右側顯示完整時間序往返訊息（含附件下載），老師 / 學員訊息視覺區分，且該對話的學員未讀訊息被標記為已讀。
- [x] AC-13：右側輸入框可行內送出回覆，送出後訊息即時出現在對話串、標記 `isFromTeacher = true`、觸發學員 email 通知，且不需開啟獨立 Dialog。
- [x] AC-14：老師回覆可附帶附件，附件顯示於對話串並可被學員下載。
- [x] AC-15：對話清單提供「待回覆」篩選，套用後只顯示有學員未讀 / 未回訊息的對話。
- [x] AC-16：無私訊時顯示空狀態而非空白 / 錯誤。

### 範圍三：老師查看測驗結果
- [x] AC-17：新增可供後台使用的 server action（如 `getQuizAttemptsForAdmin`），回傳某測驗全部學員的 attempt（含 `answers`、學員資訊、題目與正解），並做課程管理權限檢查。
- [x] AC-18：課程後台「作業」管理頁正名為「作業 / 測驗」（tab 與頁面標題），有測驗的單元顯示「查看作答結果」入口。
- [x] AC-19：測驗編輯器的「X 次作答」徽章為可點擊入口，可進入 / 開啟作答結果檢視。
- [x] AC-20：作答結果列出該測驗所有學員：姓名 / email、得分、通過與否、作答時間。
- [x] AC-21：作答結果頂部顯示統計：總作答人次、通過率、平均分，並呈現分數分布。
- [x] AC-22：可展開單一學員的單次作答，逐題顯示學員答案、正確答案、對 / 錯、（若有）題目解析。
- [x] AC-23：同一學員多次作答時，老師能看到其多次作答紀錄。
- [x] AC-24：提供「匯出 CSV」，下載內容至少含學員姓名、email、得分、通過與否、作答時間。
- [x] AC-25：測驗結果僅有權管理該課程者可查看，INSTRUCTOR 課程隔離有效；學員端行為不受影響。
- [x] AC-26：測驗尚無作答時顯示「尚無作答」空狀態而非錯誤 / 空白。

## 排除範圍（Out of Scope）

- **私訊軟刪除 / 撤回**：`LessonPrivateMessage` 目前無軟刪除欄位，需 schema migration，本次不做（可列為後續）。
- **學員端「回看自己過去測驗作答詳解」**：本次回報的是「老師看不到學員測驗結果」，學員端回看自己歷史 attempt 屬另一獨立議題，本次不處理。
- **測驗人工改分 / 重置學員作答 / 重考**：測驗為自動計分，不做作業式人工批改、不做重置或強制重考。
- **私訊全文搜尋 / 跨課程合併收件匣**：本次只做依學員聚合 + 未回篩選，全文搜尋與跨課程統一收件匣不在範圍。
- **站內即時通知（WebSocket / 紅點推播給學員端）**：私訊通知維持既有 email 機制，不新增即時推播。
- **資料庫 schema 變更**：三範圍核心行為皆以既有欄位達成，本次不新增資料表 / 欄位。
