# 學員管理改造 + 講師管理頁 — BDD 規格

## 概述

後台「用戶管理」現況：頁面叫「用戶管理」、無法依課程篩選、新增用戶不能指派課程、新增固定寄 1 小時效期重設信（不可關）、匯入完全不寄信、操作欄只有一個眼睛 icon；而「管理員/講師管理頁」其實已存在（`/admin/users/admins`）卻沒有任何側邊欄入口，等於孤兒頁。

本次改造目標：
1. 把「用戶管理」重塑為「**學員管理**」，補上課程篩選、新增/匯入時的課程指派與可選邀請信、更清楚的操作按鈕。
2. 新增獨立的「**講師管理**」頁（側邊欄「系統與法律」群組），用 email 即時搜尋來把既有用戶設為講師/管理員，或直接新建。
3. 建立共用的「邀請信 + 30 天設定密碼連結」基礎。

對象：後台管理員（ADMIN）為主，講師（INSTRUCTOR）沿用既有受限視角。

---

## 行為規格

### 場景 1：學員管理頁改名
**Given** 管理員開啟後台
**When**  查看側邊欄「學員與互動」群組與 `/admin/users` 頁面
**Then**  項目與頁面標題顯示「學員管理」，連結仍為 `/admin/users`，且仍可透過角色分頁查看全部角色用戶

### 場景 2：依課程篩選學員
**Given** 平台有多門課程與不同持有狀況的用戶
**When**  管理員在篩選列的「課程」下拉選擇某一門課程
**Then**  列表只顯示持有該課程「有效（未撤銷）授權」的用戶；可與搜尋／角色／購買狀態並用；匯出 CSV 亦只匯出符合者

### 場景 3：操作欄改為文字按鈕
**Given** 學員列表已載入
**When**  管理員看最右側操作欄
**Then**  顯示文字按鈕「編輯持有課程」，點擊導向該用戶詳情頁

### 場景 4：新增用戶可指派課程並選擇是否寄信
**Given** 管理員開啟「新增」對話框
**When**  填入名稱、Email，並（可選）指派一門或多門課程，且「寄送設定密碼邀請信」預設未勾選
**Then**  送出後建立帳號並依所選課程建立授權；只有勾選邀請信時才寄出含 30 天設定密碼連結的課程邀請信

### 場景 5：匯入學員可多課程並選擇是否寄信
**Given** 管理員開啟「匯入學員」對話框並上傳 CSV
**When**  選擇一門或多門課程，「寄送邀請信」預設未勾選
**Then**  為每位學員授權所有所選課程（重複者去重）；只有勾選時才對本次新建的帳號寄出邀請信

### 場景 6：講師管理頁入口與內容
**Given** 管理員開啟後台
**When**  查看側邊欄「系統與法律」群組
**Then**  出現「講師管理」項目（僅 ADMIN 可見），進入後只顯示管理員與講師，並可沿用既有角色切換

### 場景 7：以 email 即時搜尋把既有用戶設為講師/管理員
**Given** 管理員在講師管理頁點「新增」並選擇講師或管理員
**When**  在 Email 欄輸入關鍵字（例如輸入「AY」）
**Then**  即時列出符合的既有用戶（如 AY9487）；點選後主按鈕顯示「將已有用戶設為{講師/管理員}」，確認後該用戶角色更新

### 場景 8：查無用戶時直接新建
**Given** 管理員在同一對話框輸入了一個系統中不存在的有效 Email
**When**  下方即時搜尋查無相符用戶
**Then**  主按鈕顯示「新增該用戶」，確認後建立新帳號並設為該角色

### 場景 9：依情況自動的邀請信預設
**Given** 講師管理新增對話框
**When**  目標為「新帳號」或「既有用戶」
**Then**  「寄送設定密碼邀請信」預設值分別為「勾選」與「未勾選」；勾選時寄出告知身分並引導設定密碼的邀請信（30 天連結）

## Acceptance Criteria

### 學員管理頁 — 改名與結構
- [ ] AC-01：側邊欄「學員與互動」群組原「用戶管理」項目文字改為「學員管理」，連結仍為 `/admin/users`（行動版側邊欄同步，因共用 `sidebarGroups`）
- [ ] AC-02：`/admin/users` 頁面主標題顯示「學員管理」
- [ ] AC-03：頁面仍保有 全部／學員／講師／管理員 角色分頁，ADMIN 仍可看到全部角色用戶

### 學員管理頁 — 課程篩選
- [ ] AC-10：篩選列出現「課程」下拉，預設「全部課程」，列出當前操作者可管理的所有課程
- [ ] AC-11：選擇某課程後，列表僅顯示持有該課程「未撤銷授權」的用戶
- [ ] AC-12：課程篩選可與搜尋、角色分頁、購買狀態、分頁並存；切換課程會重置頁碼
- [ ] AC-13：「匯出 CSV」套用當前課程篩選
- [ ] AC-14：清除篩選會一併清除課程選擇
- [ ] AC-15：講師身分時課程下拉只列出其可管理課程，且結果仍受「只看自己課程學員」限制

### 學員管理頁 — 操作按鈕
- [ ] AC-20：操作欄顯示文字按鈕「編輯持有課程」，導向 `/admin/users/{id}`

### 學員管理頁 — 新增用戶
- [ ] AC-30：新增用戶對話框可指派課程，支援多選（0～多門）
- [ ] AC-31：新增「寄送設定密碼邀請信」勾選框，預設未勾選
- [ ] AC-32：送出後依所選課程為新用戶建立授權（Purchase）
- [ ] AC-33：僅當勾選時才寄出含 30 天設定密碼連結的課程邀請信；未勾選不寄任何信
- [ ] AC-34：新增講師／管理員時保留二次確認步驟

### 學員管理頁 — 匯入學員
- [ ] AC-40：匯入對話框課程選擇改為可多選（至少一門）
- [ ] AC-41：新增「寄送邀請信」勾選框，預設未勾選
- [ ] AC-42：為每位學員授權所有所選課程；重複者不重複授權
- [ ] AC-43：僅當勾選時，對本次新建的帳號寄出課程邀請信（30 天連結）；既有帳號與未勾選時不寄

### 講師管理頁
- [ ] AC-50：側邊欄「系統與法律」群組新增「講師管理」項目（僅 ADMIN 可見），連結 `/admin/instructors`
- [ ] AC-51：`/admin/instructors` 僅顯示 ADMIN 與講師（INSTRUCTOR/EDITOR）角色；非 ADMIN 存取被導離
- [ ] AC-52：沿用角色切換與「至少保留一位管理員」「不可修改自己角色」限制
- [ ] AC-53：右上「新增」提供「新增講師」「新增管理員」兩選項，皆開同一 email 即時搜尋對話框並預設對應角色
- [ ] AC-54：對話框可切換目標角色為 講師／管理員
- [ ] AC-55：Email 欄輸入時即時顯示符合（email 或姓名包含關鍵字）的既有用戶清單
- [ ] AC-56：點選既有用戶後主按鈕顯示「將已有用戶設為{角色}」，確認後角色被更新
- [ ] AC-57：查無相符且輸入有效 email 時，主按鈕顯示「新增該用戶」，確認後建立新帳號並設為該角色
- [ ] AC-58：「寄送設定密碼邀請信」預設值：新帳號為勾選、選既有用戶為未勾選
- [ ] AC-59：勾選時寄出邀請信（30 天連結，內容告知對方被賦予講師／管理員身分並引導設定密碼）

### 共用基礎
- [ ] AC-70：新增「邀請信」Email 模板，內容含：平台名稱、被加入的課程名稱或被賦予的角色身分、設定初始密碼 CTA、明示 30 天有效
- [ ] AC-71：邀請所用設定密碼連結效期為 30 天（guest 帳號走 guest activation、既有帳號走 password reset，皆以 30 天簽發）；既有 24h／1h 預設行為不變
- [ ] AC-72：新增僅 ADMIN 可用、限制回傳筆數的 email 即時搜尋 server action
- [ ] AC-73：建立用戶、授權、角色變更等寫入操作記錄至 AdminLog
- [ ] AC-74：所有新增 server action 以 Zod 驗證輸入並維持 `{ success, error?, data? }` 回傳格式

## 排除範圍（Out of Scope）

- 不改動既有金流購買流程
- 不更動 guest activation 既有 24 小時 / password reset 既有 1 小時的「預設」TTL（僅在邀請情境以參數指定 30 天）
- 不做學員端前台 UI（純後台）
- 講師管理頁不納入「課程指派」（課程指派屬學員情境）
- 不導入 email 佇列/排程，沿用既有寄信抽象層（未設定 Email 時靜默略過）
- `新增講師/新增管理員` 兩個入口在對話框內仍可自由切換角色（以對話框角色為準）
