# 多講師系統管理計劃書

## 目標

目前平台的講師只是課程上的自訂文字。新版將講師升級為正式用戶角色，讓平台可以支援多位講師共同管理課程，同時限制講師接觸平台級敏感功能。

核心目標：

- 將「學員管理」升級為「用戶管理」
- 支援角色分頁：全部、學員、講師、管理員
- 講師可以建立課程，並管理自己有權限的課程
- 管理員可以指定哪些講師可管理特定課程
- 課程、留言、優惠券必須依講師授權做後端權限控管
- 講師不可管理角色、系統設定、銷售分析、隱私權政策與服務條款

## 角色

| 角色 | 說明 |
| --- | --- |
| `USER` | 一般學員 |
| `INSTRUCTOR` | 講師，可建立與管理授權課程 |
| `ADMIN` | 平台管理員，完整權限 |
| `EDITOR` | 舊版相容角色，後端視為講師 |

`EDITOR` 不再作為新 UI 選項顯示，但為了既有站台資料相容，短期保留 enum 並視為講師權限。

## 用戶管理

「學員管理」改名為「用戶管理」，列表以分頁過濾角色：

- 全部
- 學員
- 講師
- 管理員

新增用戶 Modal 欄位：

- 名稱
- 電子郵件
- 角色

角色預設值依目前分頁：

| 分頁 | 預設角色 |
| --- | --- |
| 全部 | 學員 |
| 學員 | 學員 |
| 講師 | 講師 |
| 管理員 | 管理員 |

新增講師或管理員時必須二次確認。管理員文案需明確提示「此權限將擁有管理員權限」。

## 後台功能可見性

講師可見：

- 儀表板
- 課程管理
- 留言管理
- 媒體中心
- 用戶管理
- 訂單管理
- 優惠券

講師不可見：

- 銷售分析
- 系統設定
- 隱私權政策
- 服務條款
- 組合包

前端選單隱藏只是 UX，所有 server action、API route、頁面資料查詢都必須做後端權限檢查。

## 課程授權

資料模型新增 `CourseInstructor` 關聯表：

- `courseId`
- `userId`
- `createdById`
- `createdAt`

課程判斷規則：

- 管理員永遠可管理全部課程
- 課程未指定任何講師時，所有講師可管理
- 課程指定講師後，只有指定講師與管理員可管理
- 課程建立者也可管理該課程

課程資訊頁新增「講師管理權限」區塊：

- 預設：全部講師
- 指定講師：多選講師帳號
- 取消所有講師後回到全部講師

此權限套用到課程列表、課程資訊、定價與促銷、內容、作業、留言、評價、分析與所有課程相關 action。

## 留言管理

留言管理增加課程篩選器：

- 管理員可篩選所有課程
- 講師只能篩選自己可管理的課程
- 講師只能看到授權課程的留言

即使手動改 URL 或傳入其他課程 ID，後端仍必須阻擋未授權留言查詢、回覆、刪除與標記已讀。

## 優惠券

管理員：

- 可建立全站優惠券
- 可建立任意課程與組合包優惠券
- 可編輯所有優惠券

講師：

- 只能建立指定課程優惠券
- 至少要選一門自己可管理的課程
- 不能建立全站優惠券
- 不能建立或編輯組合包優惠券
- 只能看到與自己可管理課程相關的優惠券

## 用戶權限限制

講師可查看用戶列表，但不可：

- 新增講師
- 新增管理員
- 修改角色
- 停用或刪除管理員
- 重設他人管理權限

所有角色管理行為僅限 `ADMIN`。

## 稽核紀錄

必須記錄：

- 新增講師
- 新增管理員
- 角色變更
- 課程講師授權變更
- 講師建立或修改課程
- 講師修改優惠券
- 講師刪除留言

## 實作階段

1. 角色、用戶管理與新增 Modal
2. 課程講師授權與課程權限 helper
3. 課程、留言、優惠券權限套用
4. 後台選單、敏感頁面限制與測試檢查
