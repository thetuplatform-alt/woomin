# 新手教學設計 — 訂單管理

> 路由:`/admin/orders` ｜ 對象:查訂單、開發票、退款的講師/管理員 ｜ 預估教學:約 40 秒(5 步)

## 1. 頁面核心用途
這裡是所有交易的總帳本 — 誰買了什麼、付了沒、發票開了沒,一頁看清楚,並能進單退款或開發票。

## 2. 功能梳理(這頁能做什麼)
| 功能 | 使用者能做什麼 | 介面位置 | 教學優先級 |
|---|---|---|---|
| 營收統計卡 | 一眼看總營收、已付款/待處理/已退款筆數 | 頁面上方四張卡 | ⭐ 必教 |
| 搜尋訂單 | 用訂單編號、Email、課程名稱找單 | 篩選區左上搜尋框 | ⭐ 必教 |
| 匯出 CSV | 把目前篩選結果匯出成試算表 | 篩選區右上「匯出 CSV」按鈕 | ◐ 可帶過 |
| 狀態 / 付款方式篩選 | 依訂單狀態、付款方式縮小範圍 | 篩選區下拉選單 | ◐ 可帶過 |
| 日期區間篩選 | 限定建立時間範圍 | 篩選區「從 / 到」日期欄 | ◐ 可帶過 |
| 清除篩選 | 一鍵清掉所有篩選條件 | 有篩選時才出現 | ✕ 不教 |
| 訂單列表 | 看編號、學員、商品、金額、狀態、發票 | 中央表格 | ⭐ 必教 |
| 發票狀態 | 看每筆是否已開立發票 | 表格「發票」欄 | ⭐ 必教 |
| 查看詳情 / 退款開票 | 進單頁做退款、開立發票 | 每列最右「眼睛」按鈕 | ⭐ 必教 |
| 銷售分析 | 跳到分析頁看趨勢圖表 | 標題右上「銷售分析」 | ◐ 可帶過 |
| 分頁 | 翻頁瀏覽更多訂單 | 表格下方 | ✕ 不教 |

### 容易誤解 / 客戶常漏的點
- 退款、開發票都不在這一頁直接做,要先點「眼睛」進到單頁才有按鈕 — 新手常在列表頁找半天。
- 「發票」欄是發票狀態(待開立/已開立),跟訂單「狀態」(已付款/已退款)是兩回事,別搞混。
- 匯出 CSV 匯的是「目前篩選後」的結果,不是全部;想匯全部要先清掉篩選。

## 3. 新手教學流程
**開場白**:
> 「這裡是你的交易總帳本 — 誰買了、付了沒、發票開了沒,全在這。我帶你 40 秒學會查單、退款、開發票。」

**逐步引導:**
1. **【先看大盤】** — 特寫:`orders-stats` — 文案:「上面四張卡是你的成績單:總營收、已付款、待處理、已退款,開頁先掃一眼。」— 為何教:讓使用者先掌握全局數字。
2. **【找特定一筆單】** — 特寫:`orders-filters` — 文案:「要找某筆單?打訂單編號、Email 或課名就行。也能用下拉跟日期縮小範圍。」— 為何教:查單是最高頻動作。
3. **【訂單都在這張表】** — 特寫:`orders-table` — 文案:「所有交易列在這,金額、狀態一眼掃過去。」— 為何教:建立對主畫面的認知。
4. **【發票開了沒看這欄】** — 特寫:`orders-invoice-column` — 文案:「這欄是發票狀態,待開立還是已開立一看就懂,別跟左邊訂單狀態搞混。」— 為何教:破除最常見的欄位混淆。
5. **【退款開票進這裡做】** — 特寫:`orders-table` — 文案:「要退款或開發票?點每列最右的眼睛進單頁,按鈕都在裡面。」— 為何教:退款/開票入口隱藏在詳情頁,是客戶最常漏的點。

**可中斷 / 備註:**
- 全程可隨時關閉;只錨定常駐元素,框架會自動略過找不到的錨點。
- 第 5 步聚焦點重用 `orders-table`(眼睛按鈕在每列內、隨資料變動),文案對齊「最右眼睛」這顆常駐入口。
- 訂單為空時表格顯示空狀態,聚光燈仍可落在表格容器上。
