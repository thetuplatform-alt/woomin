# 新手教學設計 — 一般設定

> 路由:`/admin/settings` ｜ 對象:管理員(設定站名、品牌、分析、Email、儲存、影片、AI、版面的人) ｜ 預估教學:約 50 秒(6 步)

## 1. 頁面核心用途

這是整個平台的設定總開關 — 站名、Logo、品牌、分享預覽、影音、分析、版面、Email、登入方式、AI 全都集中在這一頁,用左側分類快速跳到要改的區塊。

## 2. 功能梳理(這頁能做什麼)

| 功能 | 使用者能做什麼 | 介面位置 | 教學優先級 |
|---|---|---|---|
| 分類側欄導覽 | 點左側 7 個分類,直接跳到對應設定區塊(手機版在頂部橫向) | 左側 sticky 側欄 | ⭐ 必教 |
| 設定站點名稱 | 改站名,影響瀏覽器標題、Email 寄件名、站點識別 | 站點設定 → 基本資訊 | ⭐ 必教 |
| 上傳站點 Logo | 上傳 / 更換 / 移除 Logo | 站點設定 → 基本資訊 | ⭐ 必教 |
| 設定網站網址 | 填正式網址,用於 canonical、Email 連結、callback | 站點設定 → 基本資訊 | ◐ 可帶過 |
| 設定聯絡 Email、品牌名稱 / 副標 | 填聯絡信箱與品牌顯示文案 | 站點設定 → 基本資訊 | ◐ 可帶過 |
| 設定分享預覽 | 控制連結貼到 LINE / FB / Discord 的標題、描述、圖 | 站點設定 → 分享預覽資訊 | ◐ 可帶過 |
| 查看圖片 / 附件處理狀態 | 看目前儲存方式(Local / S3)與本地路徑(唯讀,部署決定) | 影音設定 → 處理狀態 | ◐ 可帶過 |
| 設定 Cloudflare Stream | 填憑證後可上傳平台託管影片、受保護播放 | 影音設定 → Cloudflare Stream | ◐ 可帶過 |
| 設定分析追蹤 | 填 GA、PostHog、Meta Pixel / CAPI | 分析追蹤區塊 | ◐ 可帶過 |
| 設定版面 | 改 Header / Footer 導覽與頁尾內容 | 版面設定區塊 | ◐ 可帶過 |
| 設定 Email | 選 Zeabur Email / Resend / SMTP,填 API Key 與寄件者 | Email 設定區塊 | ⭐ 必教 |
| 設定登入方式 | 開 Google / Apple 登入並填憑證 | 登入方式區塊 | ◐ 可帶過 |
| 設定 AI | 填 Gemini API Key 與模型,啟用 AI 輔助 | AI 設定區塊 | ⭐ 必教 |
| 儲存設定 | 改動後底部浮出儲存列,按下才生效 | 各區塊底部 sticky 儲存列 | ⭐ 必教 |

### 容易誤解 / 客戶常漏的點

- **每個區塊各自儲存,不是一鍵存全部。** 站點、影音、分析、版面、Email、登入、AI 各有自己的儲存按鈕;改了沒按該區塊的儲存,離開就沒了。
- **儲存列平常藏起來,改了東西才浮出。** 沒看到儲存鈕是因為還沒改動,不是壞掉。
- **「圖片 / 附件處理狀態」是唯讀的。** 那塊由部署環境決定(有沒有掛 volume、有沒有設 S3),後台不提供切換,只顯示現況。
- **影音、分析、版面、Email、登入、AI 全都是「可選」。** 沒設也能正常賣課;這頁是上線後慢慢補齊用的,不必一次填完。
- **setup 階段跳過的東西都回到這裡補。** 第一次開站時略過的功能,事後一律來這頁逐項補上。
- **API Key 類欄位存進去後會遮蔽。** 看到的是提示而非原文,屬正常,不代表沒存到。

## 3. 新手教學流程

**開場白**(點問號後第一句):
> 「這是平台的設定總開關 — 站名、Email、AI 全在這。左邊分類點一下就跳過去,我帶你 50 秒認完路。」

**逐步引導:**

1. **【左邊分類,點了就跳】** — 特寫:`data-tour="settings-section-nav"`
   - 文案:「設定很多,別硬捲。左邊 7 個分類點一下,直接跳到那一區。」
   - 為何教:這頁最長,側欄是唯一的高效導覽入口;先教這個,後面每一區都靠它跳。

2. **【先把站名設對】** — 特寫:`data-tour="settings-site-name"`
   - 文案:「站名會出現在分頁標題、寄件人名字。第一件事就先改成你的品牌。」
   - 為何教:站名是最基礎、影響面最廣的一欄,新手第一個該動的就是它。

3. **【影音與圖檔怎麼存】** — 特寫:`data-tour="settings-media-status"`
   - 文案:「這塊顯示圖檔現在存哪(本地或 S3),由部署決定、不能在這切。下面才是影片設定。」
   - 為何教:儲存狀態唯讀最容易被誤會成「壞掉的開關」;一句話講清它只是顯示,順帶帶到影片設定。

4. **【Email 要選對供應商】** — 特寫:`data-tour="settings-email-section"`
   - 文案:「要寄購買通知、密碼信,先在這選 Zeabur Email / Resend / SMTP 再填金鑰。沒設就不會寄信。」
   - 為何教:Email 是高頻必設項,且「沒設=完全不寄信」是常見客訴根因,必教。

5. **【想用 AI 輔助先填這裡】** — 特寫:`data-tour="settings-ai-section"`
   - 文案:「填 Gemini API Key,就能用 AI 生講義、轉課程內容。沒填這些 AI 功能會是關的。」
   - 為何教:AI 是平台亮點功能,但需自備 Key;不講清楚,客戶會以為功能壞掉。

6. **【改完記得按儲存】** — 特寫:無(置中卡)
   - 文案:「每一區各自儲存,不是一鍵存全部。改了東西,底部會浮出儲存鈕,按下去才算數。」
   - 為何教:本頁最大踩雷點 — 分區儲存 + 儲存列預設隱藏;用置中卡收尾把這個釘死,避免「改了卻沒生效」。

**可中斷 / 備註:**

- 全程唯讀,不會替使用者改任何設定或按儲存;任何一步結束都可隨時關閉,不影響頁面。
- 自然中斷點:**第 2 步後**(已會用側欄 + 設好站名,最低限度上手)、**第 4 步後**(站名 + Email 兩大必設都帶到)。
- 中途關閉毋需復原任何 UI;再次點問號從第 1 步重新開始,不保留進度。
- 第 1、2、6 步是骨幹;若要精簡版,只留這三步即成立(導覽 → 改站名 → 記得存)。
- 第 6 步刻意用無 selector 的置中卡:儲存列(`StickySaveBar`)只在表單有改動時才出現,初次載入不在 DOM,不適合做聚光燈錨點,故改用置中卡講「分區儲存」觀念。
