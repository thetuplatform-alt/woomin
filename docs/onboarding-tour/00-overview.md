# 線上課程販售平台後台 — 新手教學引導系統【架構設計文件】

## 文件概述

本文件定義了**課程販售平台後台**的「新手教學 (Guided Onboarding Tour)」系統的整體架構、互動模式、技術實現方案和決策依據。目標是讓新進講師快速上手各個頁面的核心功能，同時保持系統輕量且易於維護。

系統應用範圍：
- **後台全頁面** — 課程列表、課程編輯（資訊、定價、邀請、內容、作業、留言、私訊、評價、分析）
- **買斷原始碼販售** — 每個客戶都需要複用和定製該框架，故**穩定性和可維護性優先**

## 1. 互動模型：問號圖示位置與啟動機制

### 1.1 問號圖示常駐位置（最終方案）

**選用位置：後台頂部導覽列（Header 右側，用戶頭像前）**

#### 決策理由

| 考量點 | 後台 Header | 課程分頁列右側 | 決策 |
|--------|-----------|------------|------|
| **可見性** | ✓ 全頁面可見，不跟隨滾動 | ✗ 課程編輯才看得到，其他頁面消失 | Header |
| **一致性** | ✓ 統一進入點，增強品牌感 | ✗ 不同頁面不同位置，學習成本高 | Header |
| **布局衝突** | ✓ Header 本身 z-index=40，樓層清晰 | ✗ TabHeader 預留的 120px 右側空間容納有限 | Header |
| **教學外頁面** | ✓ 課程列表、側邊欄導航都能用 | ✗ 無法覆蓋 | Header |
| **跨瀏覽器相容** | ✓ 固定位置，無需 shadow DOM 或浮窗 | ✗ 需特殊實現 | Header |

**具體配置：**
```
[Header 左側]  | [空白]  | [通知鈴 | 問號圖示 👈 | 用戶頭像 ✓]
                                        ↑
                                    在用戶頭像前
                                    z-index=40
```

#### 實現細節

- **位置**：`components/admin/header.tsx` 右側區塊，在用戶下拉選單前
- **圖示**：lucide-react 的 `HelpCircle` 或 `HelpSquare`，灰色（text-muted-foreground），hover 亮化
- **樣式**：24×24px 按鈕，無邊框，padding 較鬆散，滑鼠移過時背景微淡（Radix UI Tooltip 搭配）

## 2. 開場 → 逐步引導模式

### 2.1 啟動流程

```
使用者點擊問號圖示
     ↓
判斷當前頁面是否有對應的 Tour 定義
     ↓
[有] → 檢查是否已完成 / 是否超過一次查看次數
    ├─ 首次進站 → 直接進入教學流程
    └─ 曾看過 → 進入「重看模式」（無常駐 tooltip）
     ↓
[無] → Toast：「此頁面教學尚未推出」
```

### 2.2 教學流程結構

#### 第一步（開場）
- **展示對象**：整個頁面內容區域（dim 全頁，高亮核心區塊）
- **內容**：
  - **標題**：「<頁面名稱> — 快速導覽」
  - **文案**（1-2 句）：講核心用途，極簡
  - **示例**：「課程管理是你發布、編輯和監控課程的地方。下面一起來看看怎麼用。」
  - **操作**：[下一步] 或 [略過全部]

#### 中間步驟（特寫功能）
- 逐一特寫頁面上的**關鍵 UI 元素**（按鍵、表單區、統計卡片等）
- 每個步驟：
  - **目標選擇器**：穩定的 `data-tour="step-id"` 屬性
  - **Spotlight/Coachmark**：framer-motion 動畫 + 半透明遮罩圍繞該元素
  - **Tooltip**：簡短、動作導向的文案
  - **操作**：[下一步] [上一步] [略過全部]

#### 最後一步（結尾）
- **標題**：「開始使用！」
- **文案**：「你已經掌握了核心概念，盡情探索吧。」
- **操作**：[完成] → 記錄完成狀態並關閉

### 2.3 教學步驟通用文案原則

#### Do ✓
- **口語簡潔**：「點擊綠色按鍵新增你的第一堂課」優於「通過點擊新增課程按鈕來建立課程」
- **動作優先**：「現在點擊...」而非「這個按鍵的功能是...」
- **避免工程術語**：「存檔」而非「序列化資料到資料庫」
- **一句話原則**：每個步驟不超過一句（或很短的兩句）

#### Don't ✗
- 長篇大論：拆分成多個步驟，保持每個只有 15-20 字
- 被動語態：「課程可以被編輯」改為「編輯你的課程」
- 業界術語：「合併」、「發布」可以，但「預提交掛鉤」不行
- 截圖或箭頭指向：用 Spotlight 取代，更簡潔直觀

## 3. 常駐 Tooltip 邏輯

### 3.1 首次進站引導 Tooltip（只出現一次）

**触發條件**：使用者首次來到後台 + 問號圖示尚未被點擊過

**展示位置**：問號圖示上方或右側（自動選最佳）

**內容**：
```
┌──────────────────────┐
│  需要幫助？          │
│  點擊這個問號，      │
│  每個頁面都有快速導覽 │
└──────────────────────┘
       ↓ (箭頭指向問號)
```

**行為**：
- 頁面加載 500ms 後顯示
- 給予使用者 5 秒時間自動消失（或點擊任何地方消失）
- Tooltip 消失後，記錄 `onboarding:help-tooltip-seen = true`

### 3.2 教學中的步驟 Tooltip

**出現時機**：使用者進入教學流程的每個步驟

**位置**：基於該步驟的 Coachmark，自動選擇最佳位置（上方、下方、左側、右側）

**內容範例**：
```
┌─────────────────────┐
│  定價與促銷         │
│  設定課程價格和     │
│  優惠代碼           │
└─────────────────────┘
       ↓
   [Tab 被高亮]
```

## 4. 「新手教學」語義與重看機制

### 4.1 首次 vs 重看

| 狀態 | 常駐 Tooltip | Coachmark Spotlight | Tooltip 文案 | 下次進頁面 |
|-----|----------|---------|---------|----------|
| **首次進站** | ✓ 在問號旁 | ✓ 動畫特寫 | 詳細 | 不再主動跳出 |
| **重看模式** | ✗ 不顯示 | ✓ 相同特寫 | 詳細 | 每次都可手動進 |
| **已完成** | ✗ 不顯示 | - | - | 問號永遠在，隨時手動 |

### 4.2 完成狀態判斷

- **完成**：使用者點擊 [完成] 按鈕，或走完全部步驟
- **略過全部**：使用者點擊 [略過全部]，**不算完成**（下次仍會提示）
- **中途關閉**（ESC 或 X）：**不算完成**（下次進頁面時問號會輕微閃爍提示）

### 4.3 重看邏輯

- 問號圖示點擊後，永遠檢查該頁面是否有 Tour
- 若該 Tour 已完成過，進入「重看模式」
- 重看模式：Spotlight 和 Tooltip 完全相同，但省略首次開場的「整頁 dim」和「歡迎文案」
- 用戶可以隨時跳過或返回上一步

## 5. 狀態記錄方案

### 5.1 方案對比與推薦

#### 方案 A：綁帳號（資料庫）
**儲存位置**：User 表的 JSON 欄位 `onboarding_progress` 或新表 `OnboardingProgress`

**優點**：
- 跨裝置、跨瀏覽器同步
- 可統計使用者教學完成率（用於分析）
- 多人協作時，新成員登入即看到自己的進度

**缺點**：
- 需要 DB 遷移和 API 端點
- 首頁加載時需要額外查詢
- 對於一次性使用的客戶測試者（臨時帳號）麻煩

#### 方案 B：LocalStorage
**儲存位置**：瀏覽器本地

**優點**：
- 開發快，零 DB 成本
- 沒有網路延遲
- 適合快速測試和客戶演示

**缺點**：
- 跨裝置無同步
- 清除瀏覽器資料會遺失
- 無法做全域統計

### 5.2 最終推薦方案

**預設（Primary）：LocalStorage + 簡易同步層**

#### 理由
1. **初期低成本**：先用 LocalStorage 驗證用戶行為，無 DB 複雜度
2. **快速迭代**：客戶可以快速測試教學流程是否符合需求
3. **跨客戶部署**：買斷碼客戶可自主選擇是否上線 DB 同步

#### 實現策略
- **第一階段**：教學系統框架 → 所有狀態存 localStorage
- **第二階段**（可選）：若客戶要求跨裝置同步 → 加入 `useEffect` 同步到 `/api/onboarding/sync` 端點
- **降級計畫**：若 localStorage 不可用（隱私模式等），靜默降級為 session-only

### 5.3 每頁教學的狀態資料結構

#### Per-Tour Key 設計

```typescript
type OnboardingState = {
  tours: Record<TourKey, TourProgress>;
  helpTooltipSeen: boolean;
  lastUpdated: number;
};

type TourProgress = {
  tourId: string;
  completed: boolean;
  completedAt?: number;
  viewCount: number;
  lastViewedAt?: number;
  currentStep?: number;
};
```

#### LocalStorage Key 命名

```javascript
localStorage.setItem('onboarding:tours', JSON.stringify(tourProgress));
localStorage.setItem('onboarding:help-tooltip-seen', 'true');

// 查詢範例
const tours = JSON.parse(localStorage.getItem('onboarding:tours') || '{}');
const isCoursesListCompleted = tours['courses-list']?.completed ?? false;
```

## 6. 每頁教學的獨立設計與 Tour Registry

### 6.1 Tour Registry 概念

**目標**：每個頁面維護一份獨立的 Tour 定義，集中管理，易於擴展和客戶定製

#### 文件結構
```
lib/
└── tours/
    ├── index.ts
    ├── courses-list.tour.ts
    ├── course-info.tour.ts
    ├── course-content.tour.ts
    ├── course-pricing.tour.ts
    └── types.ts
```

### 6.2 Tour 型別定義

```typescript
export type TourStep = {
  id: string;
  selector: string;  // data-tour attribute value
  title?: string;
  description: string;
  position: 'top' | 'bottom' | 'left' | 'right' | 'center';
  highlightPadding?: number;
};

export type Tour = {
  id: string;
  name: string;
  description?: string;
  steps: TourStep[];
  showOpeningOverlay?: boolean;
  autoStartDelay?: number;
  requiredSelectorValidation?: boolean;
};
```

### 6.3 Tour Registry 實現

```typescript
export const tourRegistry: Record<string, Tour> = {
  'courses-list': coursesListTour,
  'course-info': courseInfoTour,
  'course-content': courseContentTour,
  'course-pricing': coursePricingTour,
};

export function getTourById(tourId: string): Tour | null {
  return tourRegistry[tourId] ?? null;
}
```

### 6.5 元素錨定：使用 data-tour 屬性

#### 為什麼選 data-tour

| 方案 | CSS Class | data-tour | ID 屬性 |
|-----|----------|-----------|--------|
| **穩定性** | ✗ 設計師改樣式易破 | ✓ 語義專屬 | ✓ 但通常用業務 ID |
| **分離** | ✗ 混入樣式關注點 | ✓ 清晰職責 | ✗ 混入業務邏輯 |
| **可讀性** | ~ | ✓ 明確意圖 | ~ |

#### 實現示例

```tsx
// components/admin/courses/course-table.tsx
<div data-tour="course-table" className="...">
  {/* 表格內容 */}
</div>

// app/(admin)/admin/courses/page.tsx
<Button asChild data-tour="create-course-btn" className="...">
  <Link href="/admin/courses/new">
    <Plus className="mr-2 h-4 w-4" />
    新增課程
  </Link>
</Button>

<div data-tour="course-filters">
  <CourseFilters />
</div>
```

## 7. 可中斷與退出邏輯

### 7.1 中斷點

| 操作 | 結果 |
|-----|------|
| **[略過全部]** | 立即關閉，不記錄為完成 |
| **ESC 鍵** | 同 [略過全部] |
| **X 按鈕** | 同 [略過全部] |
| **導航離開** | 自動關閉，記錄進度 |

### 7.2 退出後的狀態

#### Case 1：點 [完成]
```
✓ 標記 Tour 為 completed: true
✓ 記錄 completedAt 時間戳
✓ 顯示 Toast：「教學完成！」
→ 下次點問號 → 進入「重看模式」
```

#### Case 2：點 [略過全部] 或 ESC
```
✗ 不標記為完成
✓ 記錄 viewCount += 1
→ 下次點問號 → 重新從第一步開始
→ 若超過 3 次略過 → 輕微提示「如需幫助請點擊問號」
```

#### Case 3：中途導航離開
```
✓ 記錄當前 currentStep
✓ 記錄 viewCount += 1
✗ 不標記為完成
→ 下次回到此頁面 → 詢問「要從第 N 步繼續嗎？」
```

## 8. 技術選型建議

### 8.1 自製 vs 外部套件

#### 方案 A：自製（Radix Popover + framer-motion + spotlight 遮罩）

**優點**：
- 完全可控，無新套件依賴負擔
- 檔案大小小（< 30KB）
- 已有 Radix UI 和 framer-motion，無額外安裝
- 支援深度客製（動畫速度、顏色、文案等）
- 便於每個客戶調整樣式

**缺點**：
- 需實作 spotlight 遮罩演算法（圓角、位置計算）
- 要處理響應式和視窗縮放
- 鍵盤導航和無障礙性需從頭實現

#### 方案 B：引入輕量套件（driver.js 或 Shepherd.js）

**優點**：
- 開箱即用，無需自實現
- 鍵盤導航和無障礙已完成
- 浮窗位置自動調整

**缺點**：
- 增加 35-45KB 體積
- 客戶定製需修改套件或 fork
- API 可能與 Radix UI 衝突
- 買斷原始碼客戶難以集成

### 8.2 最終推薦

**方案：自製 + 漸進式優化**

#### 第一階段（MVP）
- 使用 Radix Popover + framer-motion
- 簡易 spotlight：四邊形遮罩，邊框高亮
- 不支援響應式縮放（假設教學只在桌面開始）
- 不支援鍵盤導航（可點擊按鈕完成）

#### 第二階段（穩定版）
- 加入 `useWindowSize` Hook 處理縮放
- 實現圓角高亮（Canvas 或 SVG mask）
- 支援 ESC 和 Tab 鍵
- 測試於 Safari/Firefox/Chrome

#### 第三階段（高級版）
- 支援深色模式（已有 `useAdminTheme` Hook）
- 支援多語言（i18n 整合）
- Accessibility ARIA 標籤

#### 理由
1. **成本最低**：現有套件已足夠
2. **可控性最高**：買斷客戶可輕鬆自行維護
3. **整合性最佳**：原始碼改動集中
4. **未來靈活**：後期可與其他套件解耦

## 10. 無障礙與行動裝置支援

### 10.1 鍵盤導航

| 按鍵 | 行為 |
|-----|------|
| **Tab** | 焦點在按鈕間循環 |
| **Enter** | 觸發焦點按鈕 |
| **ESC** | 退出教學 |
| **Space** | 焦點在按鈕上時，同 Enter |

### 10.2 螢幕閱讀器支援

```typescript
<div
  role="dialog"
  aria-modal="true"
  aria-label="課程管理快速導覽第 2 步"
  aria-describedby="tour-content"
>
  <div id="tour-content">教學文案</div>
</div>

// Spotlight 遮罩 aria-hidden，避免重複朗讀
<div aria-hidden="true" className="spotlight-mask" />
```

### 10.3 行動裝置（窄螢幕 < 640px）

**策略**：簡化為全螢幕 Drawer
- 若螢幕 < 640px，教學改為**全螢幕 Bottom Sheet**
- Spotlight 遮罩**關閉**（空間不足）
- 文案排版為單欄

```typescript
const isMobile = useMediaQuery('(max-width: 640px)');

if (isMobile) {
  return (
    <Drawer open={open} onOpenChange={setOpen}>
      <DrawerContent>
        {/* 全屏教學，無 Spotlight */}
      </DrawerContent>
    </Drawer>
  );
}
```

## 附錄 B:全域設計建議

## 全域設計建議

### 1. 步驟數一致性
- **現況**：步驟數落在 3–7（中位數 5），分布健康，無單頁過長。建議**硬上限維持 7 步**（course-info、course-content 已踩線），超過就拆「進階教學」或改為頁內 tooltip。
- **下限把關**：3 步的頁（invites、comments 偏短）沒問題，但要確保每步資訊密度足夠，不要為湊步數而切碎。
- **秒/步比值校準**：目前每步約 7–14 秒。course-pricing（4 步卻 70 秒）、course-info（7 步 70 秒）每步偏重，建議複查是否有單一步驟塞太多概念，必要時再拆。analytics（5 步 30 秒）最精煉，可作為「掃描型」頁面的範本。

### 2. 文案語氣統一
- **既有語氣已相當一致且優秀**：第二人稱「你」、口語動詞（「帶你走一遍」「30 秒」「一眼看光」）、講師聽得懂的白話而非系統術語。**全域沿用這套聲音**，新頁不要回到官腔。
- **開場白統一公式**：`這頁是做什麼的（一句定位）+ 我帶你 N 秒/N 步走一遍 + 可隨時關掉`。目前多數頁已符合，建議補齊「可隨時關掉/想自己看隨時可以關」這句到**每一頁**（目前只有 course-info、course-new 明講），降低新手被綁架的焦慮。
- **時間承諾口徑統一**：開場白講的秒數要對齊 `est_seconds`，且統一用「30 秒 / 40 秒 / 一分鐘」這類整數口語，不要出現「55 秒」這種精確到尷尬的數字（assignments 內部 55 秒，開場白建議講「不到一分鐘」）。
- **踩雷提示統一視覺**：凡「最易踩雷」重點（改成上線、按儲存變更、結果必選、軟刪除、連結只看一次）一律用**統一的警示樣式 + 固定措辭**（如「⚠️ 一定要…」），讓老用戶跨頁形成肌肉記憶。

### 3. 教學先後順序（動線設計）
建議在「首次上站總引導」中明示一條**主動線**，並在每頁教學結尾用「下一步去哪」串接：

> **新手第一條動線（開出第一門可販售的課）**：
> 列表 `/courses` →（按開課）新增 `/courses/new` → 資訊 `/info` → 內容 `/content` → 定價 `/pricing` → 回資訊上架（已發佈）

- **理由**：先有殼（新增）→ 填身分證（資訊）→ 鋪內容（內容）→ 定價 → 最後才上架，符合「內容沒鋪好不該先上架」的安全順序。把「改成已發佈/上架」放在動線**最後一步**，避免空課被學生看到。
- **第二圈動線（營運期）**：邀請 → 留言/私訊（回覆學員）→ 作業/測驗（批改）→ 評價（顧口碑）→ 分析（看成效）。這圈屬「課已上線後的日常」，建議**不在首訪強推**，改為使用者首次進入該頁時才觸發單頁教學。
- **依賴關係提示**：邀請、留言、私訊、作業、評價、分析都依賴「課已建立 + 有學員」，教學文案應假設使用者已走完第一圈，不必重複解釋「課程是什麼」。

### 4. 各頁之間如何不重複（去冗）
- **「儲存」概念集中教一次**：course-new、course-info、course-pricing、course-content 都有「按儲存才算數」。建議在動線**第一個出現的頁（新增）完整教**，後續頁僅用一句短提醒（「老樣子，改完按儲存」）+ 高亮按鈕，不再展開。
- **「狀態/可見性/已發佈」只在一處深講**：course-list 教「狀態決定看不看得到」、course-new 與 course-info 都教「改成上線/已發佈」。建議**概念定義收斂到 course-list**，新增/資訊頁只做「在這裡設定」的指向，避免三頁各講一套詞（上線 vs 已發佈用詞也要統一）。
- **「回覆學員」三頁（留言/私訊/評價）共用心法**：都有「公開回 vs 私下回」的概念。建議抽出共同的「回覆學員守則」一次講清，三頁各自只教該頁特有處（留言的軟刪除、私訊的未讀過濾、評價的檢舉與銷售頁開關）。
- **影片來源（YouTube/Cloudflare）只在 content 教**，其他頁不重複。

### 5. 首次上站總引導（建議要有）
- **建議做一個輕量的「歡迎卡」總引導**（非逐頁 Tour，而是一張歡迎模態 + 主動線地圖），首次登入後台時出現一次，提供三顆按鈕：「帶我開第一門課（啟動主動線）」「我自己逛逛（全部關閉但保留問號）」「之後再說」。
- **與逐頁 Tour 的分工**：總引導只負責「給地圖 + 啟動主動線」；真正的操作教學交給各頁獨立 Tour Registry（符合既定架構）。避免做成跨 11 頁的單一長流程（維護成本高、中斷率高）。
- **完成度可視化**：在問號圖示或側欄顯示「教學進度 N/11」，已看過的頁打勾，鼓勵走完但不強迫。
- **常駐問號**：維持「問號常駐 Header 右側」的決策，讓任何頁都能隨時重看該頁教學，這也是總引導之外的長期入口。
